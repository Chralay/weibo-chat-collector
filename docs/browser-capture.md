# 网页版微博快照采集

更新时间：2026-06-15

## 当前目标

先对第一个账号和第一个群聊做安全的网页版采集试跑。

当前已知信息：

- 账号显示名：`微博账号A`
- 群聊显示名：`汉语从句研究会`
- 微博入口：网页版微博
- 采集时间段：`2026-06-15 17:00:00` 到当前时间

## 安全边界

当前方案不要求你提供微博密码、Cookie、Token、Authorization 或完整请求头。

做法是：

1. 你自己在浏览器里登录微博。
2. 你自己打开目标群聊页面。
3. 项目生成一段本地网页快照脚本。
4. 你在微博页面控制台运行脚本。
5. 脚本只读取当前页面可见文本块，并发送到本机 `http://127.0.0.1:8000`。
6. 项目保存快照到本地 SQLite 数据库。

第一版只保存“页面快照”，不会立即把快照强行写入正式消息表。原因是微博网页版 DOM 结构需要先看一次真实快照，才能稳定解析发言人、时间、正文、图片、文件和链接。

## 后端接口

### 生成网页快照脚本

```text
GET /api/browser-capture/snippet
```

参数：

- `account_id`
- `group_id`
- `range_start`
- `range_end`

### 接收网页快照

```text
POST /api/browser-captures
```

由微博页面中的脚本调用。

### 查看快照列表

```text
GET /api/browser-captures
```

## 你接下来要做什么

1. 确认后端和前端都已启动。
2. 打开前端：

```text
http://127.0.0.1:5173
```

3. 进入“采集任务”。
4. 账号选择 `微博账号A`。
5. 群聊选择 `汉语从句研究会`。
6. 开始时间填写 `2026-06-15 17:00:00`。
7. 结束时间填写当前时间。
8. 点击“生成脚本”。
9. 点击“复制脚本”。
10. 回到已经打开的微博群聊页面。
11. 打开浏览器开发者工具 Console。
12. 粘贴脚本并回车运行。
13. 看到“已保存当前页面快照”提示后，回到前端点击“刷新快照”。

## 运行快照后要确认

请确认最近快照列表里出现一条新记录，并记录：

- 快照 ID。
- 文本长度。
- 页面标题是否像目标群聊。
- 是否出现浏览器安全拦截或 CORS 错误。

如果出现 CORS 或 Private Network Access 错误，需要把错误提示告诉我，我再调整本地服务响应头。

## 下一步

拿到第一条真实快照后，继续做“快照解析”：

- 识别消息时间。
- 识别发言人。
- 识别正文。
- 识别图片、文件、链接。
- 过滤红包。
- 将解析结果写入 `messages` 和 `attachments`。
